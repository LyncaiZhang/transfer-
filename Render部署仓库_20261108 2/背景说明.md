# 问津公网发布方案（2026-11-08）

## 结论

优先发布 **`09_问津智能体/pages_app/`**（Node 22 动态页移植版），不是把 Python 本机服务直接暴露。

原因：

- 已有公网版前端、判据指纹页脚、公网横幅、无密钥；
- 判据从 `criteria.json` 读取，不与 Python 版分叉；
- 2026-11-08 本地奇偶校验 **20/20 通过**；
- 本机启动 smoke test：`app_version=1.0.0-pages`、`rule_version=run_triage.v1-frozen-20261028`、`model.enabled=false`、`data=snapshot`，页面标题正常。

## 路径 A：QW Pages（首选，需平台权限）

发布参数（来自既有记录，需在具备 QW Pages 权限的会话重试）：

- 目录：`09_问津智能体/pages_app`
- 运行时：Node 22
- 入口：`server.js`
- 端口：`8081`
- 类型：dynamic
- 数据库：先 `provision_database`，再 apply `db/schema.sql`、`db/seed.sql`；或先用构建期快照（无 analyses 持久化）

环境变量：

- `SUPABASE_URL`、`SUPABASE_ANON_KEY`（只用平台注入；不写进仓库/ZIP）
- 可选 `WENJIN_SEARCH_BACKEND` / `WENJIN_SEARCH_API_KEY`
- 不配置模型 key：公网版 `model.enabled=false`，阶段由冻结判据给出；不要为了“看起来更智能”把 key 放进浏览器

发布前：

```bash
cd 09_问津智能体/pages_app
node tests/parity.mjs          # 必须 20/20
PORT=8081 node server.js       # 本机 smoke
curl -s http://127.0.0.1:8081/api/health
```

本机已执行：20/20；health ok；页面 title 正常。

已知阻塞：2026-10-29 记录中 `provision_database` / `publish` 连续 `fetch failed`（桌面受控发布通道网络级故障）。这是平台通道问题，不是代码问题；需要具备权限的会话重试，**不能自行绕行 Page/Barn HTTP**。

## 路径 B：通用 Node 22 托管（Render/Fly/Railway 等）

适用：没有 QW Pages 权限，但有一个 Node Web Service 和域名。

1. 上传 `pages_app` 目录（不含 `.env`、密钥、内部标签）；
2. Build：无（零依赖）；Start：`node server.js`；
3. 环境：`PORT` 由平台注入，`HOST=0.0.0.0`；
4. 反向代理 HTTPS；只暴露 443，不暴露 8081；
5. 可选 Supabase 环境变量；未配置时使用 seed snapshot；
6. 验证 `/api/health`、`/`、390px、打印；
7. 加访问控制/限流；公网横幅已提示“输入会经公网传输并记录，勿提交涉密材料”。

限制：这是判据移植副本，不是 Python 原进程；模型默认关闭；公开结果须人工复核，不称准确率。

## 路径 C：完整 Python 服务上 VPS（不优先）

如果必须保留 Python 原进程：

- 2 vCPU/2GB 起步；Python 3.10+；部署 `09_问津智能体` + `07_证据库` 只读副本；
- 用 Caddy/Nginx 终止 HTTPS；`WENJIN_HOST=127.0.0.1` 只给反代；
- `.env` 只放服务器 secret store；模型 key 不进入前端/仓库；
- 必须先做**公开安全子集**：不能把 `labels`、`disagreements`、`results`、`runs`、内部审计记录放进公网库；
- 成本、限流、日志与密钥轮换由负责人承担；
- 不建议用 Mac + 临时隧道作为评委正式入口（休眠、IP、安全和可用性都不可控）。
